# Аппаратное обеспечение и деплой: Hardware + Deployment

#flashcards/block-web

Какие четыре ключевых компонента аппаратного обеспечения определяют производительность сервера?
?
CPU, RAM, накопители (SSD/HDD) и GPU. Каждый компонент отвечает за свой тип нагрузки: CPU — последовательная логика, RAM — временное хранение данных, накопители — персистентность, GPU — параллельные вычисления.
Источник: Obsidian Vault/Fundamentals/Hardware/Hardware.md

Node.js на сервере упирается в какую характеристику CPU и почему?
?
Node.js — однопоточный event loop на каждое ядро, поэтому частотный буст важнее количества ядер. Четыре быстрых ядра для четырёх воркеров дадут больше, чем шестнадцать медленных.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Чем ARM-процессоры отличаются от x86-64 в контексте серверного деплоя?
?
ARM эффективнее на ватт и масштабируется до сотен ядер (AWS Graviton, Apple M), но каждое ядро слабее x86. x86 даёт высокие частоты и мощные одиночные ядра — стандарт для серверов и десктопов.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Что такое CPU throttling и при каких условиях он возникает?
?
Принудительное снижение тактовой частоты процессора из-за перегрева. Серверная стойка с плохой вентиляцией теряет до 30% производительности на реальной нагрузке. Также возникает в Kubernetes, когда CPU limit превышает request и при конкуренции под троттлится.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Почему GPU неэффективен для маленьких задач?
?
Данные копируются из RAM на видеопамять GPU через шину PCI Express, результат копируется обратно. На маленьких задачах оверхед на передачу данных перевешивает ускорение счёта. GPU выгоден на фрагментах от тысяч элементов.
Источник: Obsidian Vault/Fundamentals/Hardware/GPU.md

Какая платформа GPU является стандартом для AI-вычислений и какие библиотеки под неё заточены?
?
NVIDIA CUDA — стандарт для AI: TensorRT, PyTorch, CUDA-библиотеки заточены под неё. AMD ROCm — альтернатива, совместимая с AI-фреймворками, но на порядок хуже поддерживается.
Источник: Obsidian Vault/Fundamentals/Hardware/GPU.md

Какую роль в GPU-деплое играет VRAM и что происходит при её нехватке?
?
VRAM — главный ресурс для AI-моделей. Llama 3 8B в FP16 занимает ~16 ГБ, Stable Diffusion — 6–8 ГБ. Если VRAM не хватает, вычисления падают в RAM или CPU — производительность деградирует катастрофически. Нужен запас 20–30%.
Источник: Obsidian Vault/Fundamentals/Hardware/GPU.md

Какое приложение сильнее всего страдает от нехватки RAM на сервере?
?
Базы данных — самый чувствительный потребитель RAM. Вся активная часть данных должна помещаться в RAM, иначе каждое чтение с диска убивает latency. Для PostgreSQL с активной нагрузкой нужно 64–128+ ГБ.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Чем отличается обработка превышения memory limit в Kubernetes для CPU и RAM?
?
При превышении CPU limit под троттлится (снижает частоту). При превышении RAM limit под убивается OOMKiller — это не троттлинг, а прямое завершение процесса. Выставлять RAM limit выше реального потребления опасно: под может съесть всю память ноды.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Какой уровень oversubscription памяти безопасен для stateless сервисов, а какой — для баз данных в Kubernetes?
?
Для stateless сервисов — 120–150% переподписки, для баз данных и stateful-нагрузок — не более 100% от физической памяти ноды.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Почему HDD не подходит для баз данных под нагрузкой?
?
HDD даёт 100–200 IOPS на случайном доступе против десятков тысяч у SSD. Каждый случайный запрос к базе данных требует механического перемещения головки — latency в миллисекундах, что делает сервис неработоспособным.
Источник: Obsidian Vault/Fundamentals/Hardware/HDD.md

Какие сценарии всё ещё оправдывают использование HDD в современном деплое?
?
Холодное хранение логов, бекапы, архивы документов, стриминг больших файлов (видео, ISO-образы). Последовательное чтение HDD даёт 200–250 МБ/с. Для бэкапов БД на HDD используется потоковая запись через pg_dump.
Источник: Obsidian Vault/Fundamentals/Hardware/HDD.md

В чём разница между SATA SSD и NVMe SSD по производительности и когда какой выбирать?
?
SATA SSD — до 550 МБ/с и 100k IOPS. NVMe PCIe 4.0 — до 7 ГБ/с и 1 млн IOPS. Для веб-сервера без дискового IO хватит SATA, для баз данных, WAL-логов и AI-пайплайнов нужен NVMe.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Как типы NAND-ячеек (SLC, MLC, TLC, QLC) влияют на выбор SSD для разных нагрузок?
?
SLC — 100k циклов, enterprise; MLC — 10k циклов, серверы; TLC — 3k циклов, потребительский; QLC — 1k циклов, дёшево. Для БД с высокой записью — SLC/MLC, для кэша — TLC, для холодного хранения — QLC.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

В чём отличие StorageClass ReadWriteOnce от ReadWriteMany в Kubernetes при работе с SSD?
?
RWO — один под пишет, остальные ждут. RWX — несколько подов одновременно читают с одного диска (через NFS или GlusterFS), но throughput и latency хуже, чем у прямого RWO-диска. Для stateless-подов диск не нужен — хватит ephemeral storage.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Какой оверхед по производительности даёт каждый уровень абстракции при деплое: bare-metal, VPS, контейнер, serverless?
?
Разница между bare-metal и контейнером — 2–5%. Разница между bare-metal и VPS с KVM — 5–15% из-за прослойки гипервизора. Serverless — наибольшие накладные расходы: холодный старт до секунд.
Источник: Obsidian Vault/Fundamentals/Deployment/Deployment.md

Когда выбирать dedicated server, а когда — облачные инстансы для одного проекта?
?
Комбинация: dedicated для базы данных (zero оверхед, стабильная нагрузка), облачные инстансы для stateless-микросервисов (эластичность). Чистый dedicated оправдан при latency-sensitive нагрузке, GPU 24/7, комплаенс-требованиях.
Источник: Obsidian Vault/Fundamentals/Deployment/Deployment.md

Чем Docker внутри VPS лучше, чем чистый VPS или чистый Docker на bare-metal?
?
VPS даёт изоляцию от соседей по гипервизору, Docker внутри VPS — изоляцию между микросервисами и воспроизводимость окружений. Чистый VPS без Docker — для монолитов и БД. Чистый Docker на bare-metal — редко, для максимальной производительности.
Источник: Obsidian Vault/Fundamentals/Deployment/Virtualization.md

Какие технологии создают прослойку виртуализации в VPS и какой оверхед они дают?
?
KVM, Xen, VMware — аппаратная виртуализация с собственным ядром гостевой ОС, оверхед 5–15%. OpenVZ и LXC — контейнерная виртуализация на уровне ядра, дешевле, но одно ядро на всех соседей.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Virtual.md

Что такое burstable CPU (shared vCPU) на VPS и чем он опасен для продакшена?
?
Гипервизор даёт такты CPU, только когда они свободны от других виртуальных машин. Под нагрузкой соседа производительность скачет — latency растёт в разы. Для продакшена нужен dedicated vCPU, для стейджинга хватит burstable.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Virtual.md

Какие риски несёт vendor lock-in при выборе облачного провайдера?
?
Если база данных и очереди завязаны на managed-сервис конкретного провайдера (AWS RDS, Yandex Managed PostgreSQL), миграция к конкурентам превращается в переписывание архитектуры. Опенсорс-решения (PostgreSQL, Kafka) на собственных VPS или Kubernetes снижают этот риск.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Cloud.md

Почему dedicated server невыгоден при непрогнозируемой нагрузке?
?
Если нагрузка падает, за сервер всё равно платится полная стоимость. При нехватке мощности нужно заказывать новый сервер и переносить данные — это часы или дни, а не минуты как в облаке. Dedicated выбирают под стабильную нагрузку.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Dedicated.md

Как наличие кэша L1/L2/L3 влияет на производительность CPU-bound приложений?
?
Если рабочий набор данных превышает L3 кэш, производительность падает до скорости RAM — особенно критично для хеш-таблиц и графовых структур. Кэш сглаживает разницу между скоростью CPU и RAM.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Как работает CPU pinning и NUMA topology в Kubernetes для high-load сервисов?
?
CPU pinning привязывает поды к конкретным ядрам через CPU manager policy static, исключая переключение контекста. На NUMA-нодах (два сокета) topology manager размещает все ресурсы пода в одном NUMA-узле, иначе задержка доступа к памяти растёт.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Какая разница между холодным и горячим стартом serverless-функции и как это влияет на latency?
?
Холодный старт — функция загружается с нуля, может занимать секунды. Горячий старт — функция уже в памяти, latency в миллисекундах. Для latency-чувствительных API serverless не подходит, для фоновых задач — оптимален.
Источник: Obsidian Vault/Fundamentals/Deployment/Deployment.md

В чём проблема черепичной магнитной записи (SMR) в HDD и для каких сценариев она неприемлема?
?
При перезаписи блока SMR-диск перекладывает соседние дорожки, скорость падает до последовательной. Для интенсивной перезаписи SMR неприемлема, для write-once или редкой записи (бэкапы, архивы) — допустима.
Источник: Obsidian Vault/Fundamentals/Hardware/HDD.md

Какой объём RAM нужен для Redis под высокой нагрузкой и почему частота важнее объёма?
?
32–64 ГБ быстрой DDR5, потому что каждая микросекунда на запись считается. Redis работает целиком в RAM, latency каждого запроса зависит от скорости доступа к памяти, а не от объёма.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Как настроить requests и limits для CPU в Kubernetes для latency-чувствительного API?
?
Для API и баз данных request и limit выставляются одинаково — это исключает CPU throttling. Для фоновых задач limit в 2–3 раза выше request, так как кратковременные всплески не критичны для latency.
Источник: Obsidian Vault/Fundamentals/Hardware/CPU.md

Почему операцию TRIM важно включать для SSD в серверных ОС?
?
TRIM уведомляет контроллер SSD об освобождённых страницах для заблаговременной подготовки блоков к записи. Без TRIM производительность записи деградирует по мере заполнения диска, так как контроллер вынужден стирать блоки на лету.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Как GPU device plugin работает в Kubernetes и зачем нужен taint на GPU-нодах?
?
NVIDIA device plugin регистрирует GPU на каждой ноде, позволяя запрашивать их через `nvidia.com/gpu`. Taint на GPU-ноду + toleration на под с AI-нагрузкой изолирует дорогие GPU-ноды от обычных подов, которые заняли бы CPU/RAM без использования GPU.
Источник: Obsidian Vault/Fundamentals/Hardware/GPU.md

Что такое MIG (Multi-Instance GPU) и для чего используется?
?
Технология NVIDIA, позволяющая разделить один физический GPU (A100/H100) на несколько изолированных экземпляров. Каждый экземпляр получает часть VRAM и вычислительных блоков. Позволяет запускать несколько AI-моделей на одной карте.
Источник: Obsidian Vault/Fundamentals/Hardware/GPU.md

В чём ключевое различие между облачным деплоем и dedicated server при пиковых нагрузках?
?
Облако даёт эластичность: ресурсы добавляются за минуты через API. Dedicated server не масштабируется быстро — закупка и монтаж занимают часы или дни. При падении нагрузки облачные ресурсы отключаются, dedicated платится полностью.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Dedicated.md

Почему в РФ при выборе облачного провайдера важен не только latency, но и расположение ЦОД?
?
Для соответствия 152-ФЗ о персональных данных данные должны храниться на территории РФ. Yandex Cloud и Selectel держат ЦОД во всех городах-миллионниках. Европейские провайдеры дают больше железа за те же деньги, но без локальной привязки.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Cloud.md

Чем VPS на KVM отличается от VPS на OpenVZ по уровню изоляции?
?
KVM — аппаратная виртуализация, каждая ВМ имеет своё ядро, полная изоляция от соседей. OpenVZ — контейнерная виртуализация, одно ядро на всех, сосед может повлиять на всех модулями ядра. KVM безопаснее, OpenVZ дешевле и плотнее.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Virtual.md

При каком условии local SSD в Kubernetes выгоднее, чем сетевой облачный диск?
?
Для сверхбыстрых сценариев: WAL-логи PostgreSQL, Kafka, репликация. Local SSD привязан физически к ноде, без сетевой прослойки — минимальная latency. Не переживает переезд пода — только с StatefulSet и NodeSelector.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Как влияет пропускная способность RAM (DDR4 vs DDR5) на производительность веб-сервера и базы данных?
?
Для веб-сервера разница незаметна — bottleneck уходит в сеть или диск раньше. Для баз данных и аналитики прирост до 20% на поколение. DDR5 6400 МГц даёт ~50 ГБ/с на канал против 25 ГБ/с у DDR4.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Чем отличается сценарий использования RAM для PostgreSQL и для Redis?
?
PostgreSQL: чем больше RAM, тем больше кэша данных помещается без чтения с диска — упор на объём (64–128+ ГБ). Redis: работает целиком в RAM, каждая микросекунда на запись считается — упор на скорость (32–64 ГБ быстрой DDR5).
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Что такое многоканальный режим RAM и как он влияет на пропускную способность?
?
Две или четыре планки RAM работают параллельно по независимым каналам, увеличивая пропускную способность линейно. Важно для интегрированной графики и вычислительных нагрузок. Если модули вставлены неправильно, память работает в одноканальном режиме с половинной пропускной способностью.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Зачем нужен swap на сервере и почему для баз данных его лучше отключать?
?
Swap даёт страховку от OOM без простоя сервиса, но latency каждой страницы в swap вырастает с микросекунд до миллисекунд. Для баз данных и API это убивает производительность. Исключение — фоновые задачи, где latency не критична.
Источник: Obsidian Vault/Fundamentals/Hardware/RAM.md

Чем последовательное чтение HDD отличается от случайного по производительности?
?
Последовательное чтение (видеофайлы, архивы, бэкапы) — 200–250 МБ/с. Случайное чтение маленькими блоками — 100–200 IOPS, против десятков тысяч у SSD. Причина — механическое перемещение головки к нужной дорожке и ожидание вращения пластины.
Источник: Obsidian Vault/Fundamentals/Hardware/HDD.md

Почему интерфейс SATA является bottleneck для современных SSD?
?
SATA ограничивает пропускную способность на уровне 6 Гбит/с (~550 МБ/с). NVMe через PCIe обеспечивает до 16 линий прямого подключения к процессору с задержками в микросекундах и пропускной способностью до 7 ГБ/с на PCIe 4.0.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Что такое TBW у SSD и как он влияет на выбор диска для сервера?
?
TBW (терабайт записанных данных) — ресурс SSD, зависит от типа NAND и алгоритмов контроллера. SLC — до 100 TBW на объём, TLC — до 3 TBW, QLC — до 1 TBW. Для сервера с интенсивной записью нужен SLC или MLC.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

Как у облачных провайдеров связаны размер диска и его пропускная способность?
?
IOPS и throughput часто масштабируются линейно с размером диска. Диск на 100 ГБ получает 3000 IOPS, на 1 ТБ — 6000 IOPS. Если приложению нужно 10k IOPS, а данных на 50 ГБ, придётся заказать диск больше минимально необходимого размера.
Источник: Obsidian Vault/Fundamentals/Hardware/SSD.md

В чём главное отличие serverless от контейнерного деплоя для разработчика?
?
При serverless разработчик не видит сервер и не управляет инфраструктурой — код загружается как функция, провайдер сам решает, где его запускать. При контейнерном деплое разработчик контролирует окружение (Dockerfile), ресурсы requests/limits и сетевые настройки.
Источник: Obsidian Vault/Fundamentals/Deployment/Deployment.md

Какой сценарий деплоя выбрать для high-load API с жёсткими требованиями к latency?
?
Dedicated серверы или топовые VPS с CPU-pinning и dedicated vCPU. Без прослойки гипервизора (dedicated) или с минимальным оверхедом. Контейнеры допустимы, но с одинаковыми request и limit для исключения CPU throttling.
Источник: Obsidian Vault/Fundamentals/Deployment/Deployment.md

Почему Docker чаще всего запускают внутри VPS, а не на bare-metal напрямую?
?
VPS даёт гарантированные ресурсы и изоляцию от соседей по гипервизору, Docker — изоляцию и воспроизводимость окружений приложения. Комбинация закрывает оба требования. Чистый Docker на bare-metal — редко, когда нужна максимальная производительность без прослойки виртуализации.
Источник: Obsidian Vault/Fundamentals/Deployment/Virtualization.md

Почему overlayfs в Docker может снизить IOPS на дисковых операциях?
?
Overlayfs добавляет слой между контейнером и файловой системой хоста. При каждом чтении и записи нужно пройти через несколько слоёв образа. Для баз данных с высокой нагрузкой на диск это может дать ощутимую потерю IOPS, поэтому БД часто выносят на отдельный VPS с прямым доступом к диску.
Источник: Obsidian Vault/Fundamentals/Deployment/Virtualization.md

Какие managed-сервисы облачного провайдера создают vendor lock-in и как этого избежать?
?
Managed-базы данных (AWS RDS, Yandex Managed PostgreSQL), очереди, объектные хранилища с провайдер-специфичным API. Избежать: использовать опенсорс-решения на собственных VPS/VM, привязываться к стандартным протоколам (S3 API, PostgreSQL wire protocol), не использовать проприетарные расширения.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Cloud.md

В каких случаях dedicated server с GPU (A100/H100) дешевле облачного инстанса?
?
При нагрузке 24/7 — аренда dedicated с четырьмя A100 зачастую дешевле почасовой оплаты облачных инстансов. Если GPU загружена постоянно (тренировка моделей, рендеринг), dedicated выгоднее. При эпизодической нагрузке (инференс по запросу) облако дешевле.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Dedicated.md

Чем VDS отличается от VPS по гарантиям ресурсов?
?
Исторически VDS (Virtual Dedicated Server) обещал более жёсткую гарантию ресурсов, VPS — просто разделение. Сегодня провайдеры используют термины как синонимы. Реальный параметр выбора — тип виртуализации (KVM vs OpenVZ) и модель CPU (dedicated vs burstable).
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Virtual.md

Какой фактор при выборе VPS-провайдера критичен для пользователей из РФ?
?
Расположение дата-центра и качество каналов до российских операторов связи. Yandex Cloud и Selectel держат ЦОД во всех городах-миллионниках, latency до москвы минимальная. У европейских провайдеров (Hetzner, DigitalOcean) задержка выше, но железа больше за те же деньги.
Источник: Obsidian Vault/Fundamentals/Deployment/Environment/Virtual.md

Как определить bottleneck приложения перед выбором VPS или сборкой нод для Kubernetes?
?
Нужно ответить на три вопроса: какой bottleneck у приложения (CPU, RAM, диск, сеть) — определяется профилированием в стейджинге. Какой профиль нагрузки — стабильная или пиковая. Будет ли сервис stateful (привязка к ноде/PV) или stateless (можно раскидывать по кластеру).
Источник: Obsidian Vault/Fundamentals/Hardware/Hardware.md

Почему переукомплектованная и недокомплектованная ноды в Kubernetes одинаково плохи?
?
Переукомплектованная — ресурсы простаивают, переплата за железо. Недокомплектованная — поды конкурируют за одно и то же железо, latency растёт. Оптимум определяется мониторингом latency и утилизации в течение недели под реальной нагрузкой.
Источник: Obsidian Vault/Fundamentals/Hardware/Hardware.md

Какую роль в аппаратном обеспечении выполняет скорость обмена между компонентами по шинам?
?
Скорость обмена между CPU, RAM, накопителями и GPU через шины и интерконнекты часто становится узким местом, ограничивающим общую производительность системы независимо от мощности отдельных элементов.
Источник: Obsidian Vault/Fundamentals/Hardware/Hardware.md

Какая базовая эвристика используется для корректировки ресурсов при деплое в Kubernetes?
?
Собирать метрики по CPU, RAM, disk IO и network в течение недели под реальной нагрузкой, затем корректировать requests и limits или менять тип инстанса. Узкое место определяется по метрикам, а не по догадкам.
Источник: Obsidian Vault/Fundamentals/Hardware/Hardware.md
