## Что такое Symbol в контексте NestJS?

В NestJS, когда ты пишешь вот такое:

```ts
export const USER_REPOSITORY = 'USER_REPOSITORY';
```

или

```ts
export const USER_REPOSITORY = Symbol('USER_REPOSITORY');
```

Это **токен инъекции** — уникальный "ключ", по которому NestJS находит нужную зависимость в своём IoC-контейнере.

---

## Зачем Symbol, а не просто строка?

`Symbol('USER_REPOSITORY')` — это гарантированно уникальное значение. Два символа с одинаковым описанием **не равны** друг другу:

```ts
Symbol('X') === Symbol('X') // false !
```

Это защищает от случайного конфликта имён. Строку `'USER_REPOSITORY'` теоретически можно написать в двух разных местах и случайно "перебить" чужую зависимость. С Symbol это невозможно.

---

## Как строится связь через токен?

Вся механика — это два шага: **зарегистрировать** и **запросить**.

**1. Определяешь токен** (в отдельном файле):
```ts
export const USER_REPOSITORY = Symbol('USER_REPOSITORY');
```

**2. Регистрируешь провайдер в модуле** (говоришь NestJS: "под этим ключом — вот это"):
```ts
@Module({
  providers: [
    {
      provide: USER_REPOSITORY,   // ← токен (ключ)
      useValue: userRepository,   // ← что подставить
    },
  ],
})
```

**3. Запрашиваешь в сервисе через `@Inject(токен)`**:
```ts
@Injectable()
export class UserService {
  constructor(
    @Inject(USER_REPOSITORY) private readonly repo: UserRepository,
  ) {}
}
```

NestJS берёт токен, находит в контейнере, что под ним зарегистрировано, и подставляет это в конструктор.

## Три практических варианта регистрации

**`useValue`** — когда у тебя уже есть готовый объект (например, репозиторий TypeORM или мок для тестов):
```ts
{ provide: USER_REPOSITORY, useValue: dataSource.getRepository(User) }
```

**`useClass`** — NestJS сам создаёт экземпляр класса и разруливает его зависимости:
```ts
{ provide: USER_REPOSITORY, useClass: TypeOrmUserRepository }
```

**`useFactory`** — когда нужна логика при создании (например, передать конфиг):
```ts
{
  provide: USER_REPOSITORY,
  useFactory: (cfg: ConfigService) => new UserRepo(cfg.get('DB_URL')),
  inject: [ConfigService],
}
```

---

## Коротко: зачем всё это нужно?

Symbol-токены позволяют **отделить интерфейс от реализации**. Сервис знает только токен и тип — но не знает, что конкретно за ним стоит. Это даёт:

- **Подменяемость**: в тестах подставляешь мок под тот же токен, сервис не меняется.
- **Отсутствие циклических импортов**: сервис не импортирует класс репозитория напрямую.
- **Чистую архитектуру**: зависишь от абстракции, а не от конкретики.
